# 배포 가이드

**요약: Streamlit Community Cloud 에는 화면(UI)만 올릴 수 있다. 백엔드는 다른 곳에 있어야 한다.**

Community Cloud 는 Docker 를 실행해 주지 않고, 앱이 쓰는 포트 외에는 외부에서 들어오는 연결을 받지 못한다.
이 프로젝트는 Postgres(pgvector)와 MinIO 컨테이너, 그리고 별도 프로세스인 FastAPI 백엔드를 쓴다.
따라서 `docker compose` 를 전제로 한 지금 구성을 그대로 올릴 수는 없다.

## 1. 선택지 세 가지

| 방식 | 가능 여부 | 드는 일 | 언제 쓰나 |
|---|---|---|---|
| **A. 로컬 실행** | 지금 바로 됨 | 없음 | 팀 내부 시연, 개발 |
| **B. UI 만 Cloud + 백엔드는 다른 호스트** | 됨 | 백엔드 호스팅 + 관리형 DB | 링크 하나로 외부에 보여줄 때 |
| **C. 전부 Cloud 한 프로세스** | 조건부 | 코드 구조 변경 + 관리형 DB | 백엔드 호스팅 비용을 피하고 싶을 때 |

발표·제출용으로 링크가 필요하면 **B** 를 권한다. 아래에 절차가 있다.
그냥 팀 안에서 돌려보는 목적이면 **A**([팀_시작하기.md](팀_시작하기.md))로 충분하다.

## 2. Community Cloud 가 주는 것과 못 주는 것

공식 문서 기준이다. 출처는 각 항목 끝에 적었다.

| 항목 | 내용 |
|---|---|
| 메모리 | 최소 690 MB ~ 최대 2.7 GB (문서상 "2024년 2월 기준", 예고 없이 바뀔 수 있음) |
| CPU | 최소 0.078 코어 ~ 최대 2 코어 |
| 저장공간 | 최대 50 GB |
| 절전 | **트래픽이 12시간 없으면 잠든다.** 깨우려면 방문자가 안내 페이지에서 버튼을 눌러야 한다. 자동으로 깨지 않는다 |
| Docker | 지원하지 않는다. 컨테이너화는 플랫폼이 알아서 하며 이미지를 줄 수 없다 |
| 들어오는 연결 | 앱의 HTTPS/웹소켓 포트 하나뿐이다. 다른 포트를 열 수 없다 |
| 나가는 연결 | 공개 HTTPS 호출은 실제로 동작한다. 연결 허용 목록이 필요할 때 쓰라고 발신 IP 18개를 공개한다 |
| 백그라운드 프로세스 | 문서화된 지원이 없다. 12시간 절전과 맞물려 신뢰할 수 없다 |
| 비밀값 | 배포 화면에 TOML 을 붙여 넣고 `st.secrets` 로 읽는다. 최상위 키는 환경변수로도 노출된다 |
| Python 버전 | 배포할 때 드롭다운에서 고른다. 기본값 3.12. **배포 후에는 못 바꾼다**(삭제 후 재배포) |

## 3. 의존성 파일은 어떤 것이 쓰이나

Community Cloud 는 **엔트리포인트가 있는 디렉터리를 먼저 찾고, 그다음 저장소 루트를 찾는다.**
각 위치에서는 `uv.lock` → `Pipfile` → `environment.yml` → `requirements.txt` → `pyproject.toml` 순으로 우선한다.
찾은 **첫 번째 파일 하나만** 쓴다.
([출처](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/app-dependencies))

이 저장소는 루트에 `uv.lock` 이 있다. 그대로 두면 백엔드 의존성까지 전부 설치된다.
그래서 UI 전용 목록을 엔트리포인트 옆에 두었다.

```
ui/requirements.txt      ← 엔트리포인트(ui/app.py) 옆 → 이것이 이긴다
uv.lock                  ← 루트 → 무시된다
```

`ui/requirements.txt` 에는 두 줄뿐이다.

```
streamlit==1.63.0
httpx==0.28.1
```

UI 는 `src/baseball/` 을 전혀 import 하지 않는 순수 SSE 클라이언트이므로 이것으로 충분하다.
깨끗한 가상환경에 이 두 패키지만 설치하고 화면을 렌더링해 **예외 0건**을 확인했다.

## 3-A. `.streamlit/config.toml` 의 `[server]` 설정 (조치 완료)

**저장소의 `config.toml` 에서 바인딩 주소와 포트를 뺐다.** 그대로 두면 배포본이 뜨지 않을 수 있었다.

원래는 로컬 보안을 위해 이렇게 들어 있었다.

```toml
[server]
address = "127.0.0.1"
port = 8501
```

문제는 두 가지다.

- Community Cloud 가 **덮어쓴다고 문서화한 옵션은 다섯 개뿐**이다.
  `runOnSave`, `enableXsrfProtection`, `showErrorDetails`, `fastReruns`, `gatherUsageStats`.
  `server.address` 는 이 목록에 없다. Cloud 가 덮어쓴다는 보장이 없다.
- `server.address` 는 화면 표시용이 아니라 **실제 소켓 바인딩**이다.
  파일에 값을 적으면 "수동 지정" 으로 간주되어 듀얼스택 확장이 꺼지고 루프백에만 묶인다.
  Cloud 의 헬스체크는 `localhost:8501` 로 접속하는데, 이 이름이 파드 IP(`10.x.x.x`)로 풀리는 사례가
  포럼 오류 로그에 남아 있다. 루프백에만 묶인 서버는 그 접속을 거부한다.

`port = 8501` 도 함께 뺐다. 포트를 수동 지정하면 포트 충돌 시 다음 포트를 찾는 대체 동작이 꺼지고
프로세스가 그대로 종료된다. 얻는 것이 없다.

**로컬의 루프백 바인딩은 그대로 유지된다.** 설정 우선순위가 `명령행 > 환경변수 > 설정 파일` 이므로
`make ui` 가 플래그로 강제한다. 로컬에서 직접 확인한 결과다.

| 실행 방식 | 적용된 주소 |
|---|---|
| `config.toml` 만 (= Cloud) | 지정 없음 → Streamlit 기본값 |
| `make ui` (= 로컬) | `127.0.0.1:8501` |

`tests/test_theme_config.py::test_server_binds_loopback` 이 두 가지를 함께 단언한다.
설정 파일에 `address`·`port` 가 없을 것, 그리고 Makefile 의 `ui` 타깃이 루프백 플래그를 넘길 것.

`[theme]` 계열은 그대로 둔다. Cloud 가 덮어쓰지 않으며, 저장소 루트의 `.streamlit/config.toml` 을 읽는다.
`[theme.light]` / `[theme.dark]` 분리 테마는 streamlit 1.51.0 이상에서 동작하고 이 프로젝트는 1.63.0 을 고정한다.
`[[theme.fontFaces]]` 를 바꾸면 핫리로드가 되지 않으므로 Cloud 에서 앱을 재부팅해야 한다.

`[browser] gatherUsageStats = false` 는 Cloud 에서 `true` 로 덮어써진다. 남겨 두어도 무해하지만 효력은 없다.

## 4. 메모리는 얼마나 쓰나 (실측)

macOS·Python 3.12 에서 단계별로 잰 값이다. 상주(RSS)와 최대치를 함께 적었다.

| 구성 | 상주 | 최대 |
|---|---|---|
| 인터프리터만 | 11 MB | 11 MB |
| **UI 전용** (streamlit + httpx) | **52 MB** | 52 MB |
| + 백엔드 모듈 (FastAPI·LangChain·OpenAI) | 168 MB | 168 MB |
| + Kiwi 형태소 분석기 | 422 MB | 422 MB |
| + BM25 인덱스 (701 청크) | 595 MB | 634 MB |
| **올인원 전체 상주** | **600 MB** | **626 MB** |

읽는 법은 두 가지다.

- UI 만 올리면 52 MB 다. 최소 보장치 690 MB 안에서 여유가 크다.
- 올인원도 600 MB 로 **메모리만 보면 최소 보장치 안에 들어간다.** 다만 여유가 90 MB 뿐이라 동시 접속이 늘면 위험하다.

즉 올인원을 막는 것은 메모리가 아니라 **Postgres 와 MinIO 다.** 둘 다 Docker 없이는 뜨지 않는다.

## 5. 방식 B — UI 는 Cloud, 백엔드는 다른 호스트 (권장)

### 5.1 필요한 것

| 구성 | 옮길 곳 | 비고 |
|---|---|---|
| Streamlit UI | Streamlit Community Cloud | 무료 |
| FastAPI 백엔드 | Docker 를 돌릴 수 있는 호스트 | Render, Railway, Fly.io 등. **HTTPS 공개 주소 필요** |
| Postgres + pgvector | 관리형 서비스 | Supabase, Neon 등 pgvector 확장을 지원하는 곳 |
| MinIO | 같은 호스트의 MinIO 또는 S3 호환 스토리지 | 원문 PDF 링크용. 없으면 "원문 PDF 열기" 버튼만 빠진다 |

백엔드 호스트는 **공개 HTTPS 주소**를 줘야 한다. Community Cloud 앱은 사용자의 브라우저가 아니라
Cloud 서버에서 백엔드를 호출하므로, `127.0.0.1` 이나 사내망 주소로는 닿지 않는다.

### 5.2 백엔드 준비

1. `PG_DSN` 을 관리형 Postgres 주소로 바꾼다. 스키마와 색인을 그 DB 에 한 번 만든다.
   ```bash
   PG_DSN='postgresql://...' ./bin/br python -m baseball.db ensure
   PG_DSN='postgresql://...' ./bin/br python -m baseball.storage sync
   PG_DSN='postgresql://...' ./bin/br python -m baseball.ingest
   ```
   pgvector 확장이 켜져 있어야 한다. `ensure` 가 `CREATE EXTENSION IF NOT EXISTS vector` 를 수행하지만,
   관리형 서비스에 따라 대시보드에서 먼저 켜 줘야 하는 곳도 있다.

2. 백엔드를 호스트에 올린다. 기동 명령은 호스트가 주는 포트에 바인딩해야 한다.
   ```
   uvicorn baseball.api:app --host 0.0.0.0 --port $PORT
   ```
   로컬용 `make api` 는 `127.0.0.1` 에 묶으므로 그대로 쓰면 안 된다.

3. CORS 는 건드릴 필요가 없다. 기본값이 로컬 주소 두 개로 좁혀져 있지만,
   Streamlit 은 브라우저가 아니라 **Cloud 서버 프로세스에서** 백엔드를 호출하므로 CORS 검사를 타지 않는다.
   브라우저에서 백엔드를 직접 부르는 코드를 나중에 추가한다면 그때 `CORS_ORIGINS` 환경변수에 앱 주소를 넣는다.

4. 백엔드는 기동할 때 Kiwi 와 BM25 인덱스를 만든다. 약 600 MB 메모리와 수 초의 기동 시간이 필요하다.
   메모리 512 MB 짜리 무료 티어에서는 뜨지 않는다.

### 5.3 Cloud 에 UI 올리기

1. 저장소를 GitHub 에 push 한다. 아래 파일이 모두 올라가 있어야 한다.
   - `ui/app.py`, `ui/api_client.py`, `ui/theme.py`
   - `ui/requirements.txt`
   - `.streamlit/config.toml` (루트에 있어야 한다. Cloud 는 저장소 루트에서 앱을 초기화한다)

2. share.streamlit.io 에서 **New app** → 저장소·브랜치 선택 →
   **Main file path** 에 `ui/app.py` 를 넣는다. 슬래시(`/`)만 쓴다.

3. **Advanced settings** 에서
   - Python version: **3.12**
   - Secrets 에 다음을 붙여 넣는다.
     ```toml
     API_BASE_URL = "https://백엔드-주소"
     ```

4. Deploy.

UI 는 백엔드 주소를 이 순서로 찾는다. 코드 수정 없이 환경이 바뀐다.

```
환경변수 API_BASE_URL  →  st.secrets["API_BASE_URL"]  →  http://127.0.0.1:8000
```

### 5.4 배포 후 확인

- 사이드바에 `● 준비됨` 과 청크 수가 보이면 백엔드까지 연결된 것이다.
- `준비 안 됨` 이면 백엔드가 죽었거나 `API_BASE_URL` 이 틀렸다. UI 자체는 정상 렌더링된다.
  (백엔드에 못 닿아도 화면이 깨지지 않도록 되어 있다. 클린 환경에서 확인함)

## 6. 방식 C — 전부 한 프로세스로 Cloud 에 올리기

메모리는 된다(600 MB). 막히는 것은 데이터 저장소다. 하려면 이만큼 손대야 한다.

1. **Postgres 를 관리형으로 옮긴다.** 필수. Cloud 안에서는 DB 를 띄울 수 없다.
2. **MinIO 를 뺀다.** PDF 원문 링크 기능을 포기하거나 S3 호환 스토리지로 바꾼다.
3. **FastAPI 를 없애고** Streamlit 안에서 `RagService` 를 직접 부른다.
   Cloud 는 앱 포트 하나만 열어 주므로 같은 프로세스에서 uvicorn 을 따로 띄울 수 없다.
   `ui/api_client.py` 의 SSE 호출을 `RagService.astream()` 직접 호출로 바꿔야 한다.
4. **의존성 파일을 바꾼다.** `ui/requirements.txt` 를 지우거나 백엔드 의존성을 모두 넣어야 한다.
5. 기동할 때마다 Kiwi 로드와 BM25 빌드에 수 초가 걸린다. 12시간 절전에서 깨어날 때마다 반복된다.

얻는 것에 비해 바뀌는 코드가 많고, FastAPI 백엔드라는 과제 요건에서도 멀어진다. 권하지 않는다.

## 7. 공통 주의

- **비밀값을 커밋하지 않는다.** `.env` 는 `.gitignore` 에 있다.
  Cloud 에서는 Secrets 화면에만 넣는다. 저장소에 `secrets.toml` 을 만들지 않는다.
- **OpenAI 키는 백엔드에만 둔다.** UI 는 키를 쓰지 않는다. UI 쪽 Secrets 에 키를 넣을 이유가 없다.
- **공개 배포는 곧 비용이다.** 아무나 질문을 던질 수 있고 요청마다 OpenAI 요금이 나간다.
  실측 요청당 약 $0.00043 이다. 공개 전에 OpenAI 프로젝트에 지출 한도를 걸어 둔다.
- **12시간 절전**은 무료 티어의 정상 동작이다. 시연 직전에 한 번 열어 깨워 둔다.
- MinIO 고정 이미지는 CVE-2025-62506 미패치 상태다. 공개 호스트에 그대로 올리지 않는다.
